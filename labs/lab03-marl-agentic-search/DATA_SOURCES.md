# Паспорт данных и поиска

Источник: [MIRACL topics и qrels](https://huggingface.co/datasets/miracl/miracl), официальная ревизия `5be20db9509754dadad47689368639fcec739c00`; [MIRACL corpus](https://huggingface.co/datasets/miracl/miracl-corpus), статья [Zhang et al.](https://arxiv.org/abs/2210.09984). В карточках обоих наборов указана лицензия Apache-2.0; фрагменты происходят из Wikipedia, учитывайте условия первоисточника. Локальные topics/qrels взяты без изменений из lab01/data/raw; контрольные суммы указаны в data/manifest.json.

Полный русский корпус используется через имеющийся полнотекстовый индекс ВКР `.local/full-miracl-ru-v1/index/miracl_ru_fts.sqlite`, открываемый только для чтения. Скрипт ВКР `scripts/run_full_miracl_overnight.py` описывает сборку 20 официальных частей `miracl/miracl-corpus`, ревизия `main` на момент сборки; в его manifest сохранены SHA-256 исходных архивов, но фиксированный commit исходного корпуса там не указан. Таблица completed_shards содержит 20 частей и 9 543 918 фрагментов, что согласуется с документацией ВКР. Полный SHA-256 готового индекса и точный путь фиксируются в `data/retrieval_full/timing.json`; это проверяет конкретный локальный артефакт, но не доказывает независимо идентичность каждой записи оригиналу. Для воспроизведения нужен этот индекс либо аналогичный SQLite FTS5, соответствующий ожидаемому хэшу. Копия 41 007 фрагментов в lab01 использована только для проверки наличия размеченных документов и не участвует в построении или поиске индекса: она сформирована с использованием train/dev qrels и непригодна как независимый корпус оценки.

Исходные темы: official train 4 683, dev 1 252. Удалены три train-запроса, совпадающие с dev после casefold и нормализации пробелов, записи лежат в data/dropped_duplicates.json. На основе хеша нормализованного запроса с seed 42 пары train/validation и test/application разделены в соотношении 80/20, затем по хешу qid, без qrels, выбраны соответственно 400/100/150/100 запросов. Разных сплитов с одинаковыми нормализованными запросами нет. Файлы запросов содержат qid/query/official_split; файлы qrels отделены и содержат qid/docid/rel. Все qrels выбранных запросов покрыты 41-тысячным справочным подмножеством, что косвенно подтверждает наличие в полном индексе при условии корректности его сборки; прямой docid lookup по полному индексу не проводился. Тест и application взяты из official dev, это не официальный тест MIRACL и их нельзя позиционировать как ранее не использовавшиеся для любых других работ: в lab01 и ВКР использовали тот же источник dev.

До окончательной фиксации поиска были просмотрены агрегированные числа пустых выдач для прежнего AND-варианта на test/application; метки и метрики качества на них не использовались. Это ограничивает строго слепой характер проектирования retrieval. Новые правила выбраны по первым 50 train-запросам: три варианта используют первые два содержательных слова AND, последние два AND и два самых длинных содержательных слова AND. Стоп-слова и детерминированная токенизация заданы в коде; при отсутствии содержательных слов используется исходный вопрос. SQLite FTS5 unicode61, BM25 с настройками по умолчанию, до пяти документов, сортировка по score и docid. Ограничение каждого запроса — 3 секунды; прерванный запрос возвращает пустой список и статус timeout. Это выбор одного из заранее созданных запросов, а не свободная генерация реформулировки или свидетельство многошагового вывода. qrels не читаются поиском и не передаются в данные выдачи. Результаты лежат в `data/retrieval_full/{split}.jsonl`: qid, query, variants; у каждого варианта query, operator, hits, latency_s, status; каждый hit содержит id, title, text, score. Значения latency зависят от компьютера и состояния кэша; хэши файлов результатов поэтому будут меняться между запусками.

Воспроизведение на этой машине из папки лабораторной: `D:\Anaconda3\python.exe data_pipeline.py --precompute`. Можно передать `--source`, `--target` и `--index`; подготовка зависит от локальных данных lab01 и полного FTS5-индекса ВКР и не скачивает данные автоматически. Интерпретатор должен включать sqlite3 с FTS5. Сначала дождитесь формирования `data/retrieval_full/timing.json` и проверьте full_corpus, идентификатор индекса и SHA-256 всех четырёх файлов выдачи. Не используйте неполные или старые файлы выдач. Неразмеченные документы не следует считать доказанно нерелевантными: qrels неполны.
